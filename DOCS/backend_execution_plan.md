## المرحلة 1: مراجعة وتحليل ملفات التوثيق
- تم تحليل الملفات:
  - shahania_forms_catalog.xlsx: يحتوي على جميع النماذج والحقول المطلوبة.
  - shahania_full_ddl_v1.sql: تعريفات الجداول والعلاقات الأساسية (مدرسة، عام دراسي، فصل، ولي أمر، طالب، تسجيل، مواد، صفوف، معلمين، ...).
  - الكل_تطبيقات_نماذج_حقول.md: كتالوج شامل لكل النماذج والحقول، مع تصنيف المجالات والدورية، وحقول قياسية موروثة.
  - مرميد.txt: رسم علاقات ER بين الكيانات الرئيسية.
  - هيكلة.md: شرح معماري شامل، هيكلة المجلدات، توزيع التطبيقات، أفضل الممارسات، توصيف كل app.

### قائمة النماذج الأساسية المطلوبة:
- school, academic_year, term, guardian, student, enrollment
- subject, class_room, teacher, teaching_assignment
- attendance_record, behavior_incident, behavior_committee, behavior_sanction, offense_code
- exam, exam_session, exam_result
- clinic_visit, medication_log
- bus, route, route_stop, student_rider, ride_log
- library_title, library_copy, library_loan
- quality_standard, quality_indicator, quality_evidence
- staff, staff_attendance, leave_request, disciplinary_action, performance_review
- timetable_slot, timetable_rule
- notice, audit_log

### العلاقات الرئيسية:
- كل نموذج مرتبط بمدرسة وعام دراسي وفصل (حقول قياسية)
- علاقات FK واضحة بين الطالب وولي الأمر، الطالب والتسجيل، المدرسة والتسجيل، الصفوف والمعلمين، ...
- علاقات ER موثقة في مرميد.txt

### ملاحظات:
- يجب توريث الحقول القياسية في كل نموذج (school_id، academic_year، term، form_uuid، created_at، created_by، updated_at، status)
- بعض الحقول حساسة (health) يجب تشفيرها (BYTEA)
- يجب مطابقة جميع التسميات والحقول مع ملفات التوثيق بدقة
- يوجد 148 نموذج حسب الكتالوج النهائي

### مخرجات التحقق:
- قائمة شاملة بالنماذج والحقول والعلاقات المطلوبة موثقة أعلاه
- لا فروقات جوهرية بين ملفات التوثيق، الهيكلة متسقة
- جاهزية للانتقال للمرحلة الثانية (مطابقة النماذج في Django)
