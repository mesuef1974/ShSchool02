# منصة مدرسة الشحانية الإعدادية الثانوية

## **الملف الشامل لهيكلة المشروع (Back‑End + Front‑End)**

**Stack:** PostgreSQL + Django (Back‑End) — Django Templates + Tailwind CSS + HTMX + Alpine.js (Front‑End)\
**الإصدار:** v1.0 — **جاهز للتنفيذ الفوري**—RT L، سريع، آمن، قابل للتوسع والصيانة.

> هذا المستند يقدّم **هيكلة احترافية كاملة** للمشروع (مجلدات + إعدادات + قواعد تنظيمية + أفضل الممارسات) بالإضافة إلى **نماذج كود** أساسية للانطلاق بثقة.

***

## 1) نظرة عامة على المعمارية

*   **Monolith Modular**: مشروع Django واحد مُقسّم إلى **Apps بحسب المجال** (Students, Attendance, Health …) لضمان الفصل المنطقي وسهولة التطوير.
*   **PostgreSQL** قاعدة البيانات الافتراضية (دعم JSONB، فهارس جزئية، توافق مستقبلي مع RLS).
*   **Server‑Rendered UI** عبر **Django Templates + HTMX + Alpine.js**: واجهات خفيفة وسريعة **بدون تعقيد SPA**، مع نقاط REST لاحقة عند الحاجة.
*   **Tailwind CSS** للسرعة والاتساق والتصاميم المتجاوبة (مع RTL).
*   **Celery + Redis** للمهام الدورية (تقارير/إشعارات/أرشفة).
*   **Docker Compose** لبيئات التطوير/الاختبار والنشر.

***

### توصيات تنظيمية للباك‑إند

*   **نماذج الهوية:** `UUIDField` كمفتاح أساسي لكل الجداول.
*   **التدقيق:** `TimeStamped`, `AuditLog` لكل عمليات القراءة/الكتابة الحساسة.
*   **التعامل مع الملفات:** `media/` + توقيع روابط التحميل/Expiry إذا لزم.
*   **المهام:** Celery لـ (إرسال الإخطارات/التقارير/الأرشفة) + Redis Broker.
*   **الفهرسة:** فهارس على (التاريخ، الصف، المادة، الحالة) للحضور/النتائج/السلوك.

## 5) نمط قواعد البيانات (مختصر)

*   **Students/Guardians/Enrollment**
*   **AttendanceRecord**: `(enrollment, date, period, status[P/A/E/L/ED])` + فهرس على `date`.
*   **Behavior**: `OffenseCode/Incident/Committee/Sanction`.
*   **Assessments**: `Exam → Session → Result`.
*   **Health**: `ClinicVisit/MedicationLog` (تشفير حقول حسّاسة في طبقة التطبيق).
*   **Transport**: `Bus/Route/RouteStop/StudentRider/RideLog`.
*   **Library**: `Title/Copy/Loan`.
*   **Quality (QNSA)**: `Standard/Indicator/Evidence`.
*   **HR**: `Staff/StaffAttendance/Leave/Disciplinary`.
*   **Timetable**: `TimetableRule(JSONB)/TimetableSlot` (Unique per class/day/period).
*   **Notifications/Audit**.

> الممارسات: UUID PKs، فهارس على الحقول الزمنية، Soft‑Delete عند الحاجة، **قيود تفرد** تمنع تضارب الجدول.

## 6) الأمان والامتثال

*   **حماية البيانات (PDPPL)**:
    *   **موافقة ولي الأمر** لمعالجة بيانات القُصّر (حقل Boolean + توقيت).
    *   **تشفير الحقول الحسّاسة** في التطبيق (AES‑GCM/FPE)، تخزينها في DB كـ `BYTEA`.
    *   **سجل تدقيق (AuditLog)** على القراءة/الكتابة للحقول الحساسة.
    *   **تقليل الظهور**: إخفاء الحقول الصحية والسلوكية عن غير المختصين في القوالب/العروض.
*   **الصحة المدرسية (NHS)**: نماذج الزيارة/الطوارئ/الصرف + تقارير مؤشرات دورية.
*   **سياسات الاحتفاظ (Retention)**: AY+5 مبدئيًا—مهام Celery للأرشفة الدورية.
*   **الأدوار (RBAC)**: مجموعات Seed (مدير/نواب/مرشد/ممرضة/مسجّل/مكتبي/مشرف نقل/…)، وتقييد الواجهات/الأزرار بناءً على الدور.

## 8) Docker و Celery

**docker-compose.yml (مختصر):**

```yaml
version: "3.9"
services:
  db:
    image: postgres:15
    environment:
      POSTGRES_DB: shahania_db
      POSTGRES_USER: sh_user
      POSTGRES_PASSWORD: StrongPass!
    ports: ["5432:5432"]
    volumes: [dbdata:/var/lib/postgresql/data]
  redis:
    image: redis:7
    ports: ["6379:6379"]
  web:
    build: .
    command: bash -c "python manage.py migrate && gunicorn core.wsgi:application -b 0.0.0.0:8000"
    environment:
      DATABASE_URL: postgres://sh_user:StrongPass!@db:5432/shahania_db
      REDIS_URL: redis://redis:6379/0
    volumes: [.:/app]
    ports: ["8000:8000"]
    depends_on: [db, redis]
  worker:
    build: .
    command: celery -A core worker -l info
    environment:
      DATABASE_URL: postgres://sh_user:StrongPass!@db:5432/shahania_db
      REDIS_URL: redis://redis:6379/0
    depends_on: [db, redis]
volumes: { dbdata: {} }
```

## 9) الاختبارات والجودة

*   **pytest + pytest‑django**: اختبارات وحدات لكل App (Models/Services/Views).
*   **Factory Boy** لتوليد بيانات اختبار.
*   **Coverage** ≥ 80% على النطاقات الحساسة (الحضور/السلوك/الصحة/النتائج).
*   **Lint**: flake8/black/isort.
*   **CI**: GitHub Actions (Lint + Test + Build Docker + Push).

***

## 10) CI/CD وخط النشر

1.  **Branching**:
    *   `main` للإنتاج — `develop` للتطوير — **Feature Branches** لكل نطاق.
2.  **CI**: تشغيل lint/tests وبناء Docker على Pull Requests.
3.  **CD**:
    *   Staging: تحديث تلقائي بعد دمج في `develop`.
    *   Production: نشر يدوي مع Migration/Backup/Health‑check.

***

## 11) Naming & Conventions

*   **الموديلات:** مفرد واضح `Student`, `ExamResult`.
*   **الجداول الحساسة:** لاحقة `*_enc` للحقل المشفر في الـModel (توضيح فقط داخل الكود).
*   **المسارات/الأسماء:** `students:detail`, `attendance:class_daily`.
*   **القوالب:** `app/view.html` و `app/partials/*.html`.

## 12) خارطة الطريق (إصدارات لاحقة)

*   **OpenAPI (YAML)** لواجهات REST عندما نفعّل بوابة خارجية (موبايل/SPA).
*   **RLS** على Postgres إن أردنا طبقة حماية صف‑بصف على DB.
